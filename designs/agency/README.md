# GSP 3.0 agency portal · coded prototype

The agency (recruitment partner) side of GSP 3.0, built screen by screen. The plan and build order are in [`PLAN.md`](PLAN.md). Changes agreed in review meetings are listed by page in [`REVIEW.md`](REVIEW.md).

**Built so far:**
- **Sign in**, the portal's front door, in Liquid Glass: username and password, a forgotten-password flow, and "Become a GSP partner" for new agencies.
- **Becoming a partner**, the screen behind "Become an upGrad GSP Partner" on upgradgsp.com (`app.globalstudypartners.com/signup` today), on the same photo, statement and glass panel as sign-in (no steps beside it): a short form (name, business, country, business email, password), then a 6-digit code to the email, which creates the account. The rest of registering happens in the portal: the business details and documents, on Home, with everything else locked until they've gone to GSP.
- **Find courses:** optionally for one of the agency's students, one search box that reads plain words and forgives typos, the five things the brief needs before showing results plus the intake, filters, sorting, a Student view that hides earnings, a shortlist and a course detail sheet.
- **Students** (once GSP has verified the agency): an empty page that explains how to start, the list with contact details to copy, the counsellor (a name with a pencil to change it, after a confirmation), how ready each profile is and the applications, each student's record, and **Add a student** (a dialog in the middle of the window, which can expand) with passport autofill, duplicate checks and the student's documents, all at once or later from the profile.
- **Applications** (once GSP has verified the agency): owner tiles, filters by how far each application has got (New, Applied, Offer received, Deposit paid, Enrolled and, since 3 Nov in every role, **Closed**; the search box says “Student or course”), a date range, the list (downloadable as CSV; since 6 Nov, every role's list tags each application **Primary** or **Secondary** for its student), one page per application (the tag under the student's name; **GSP · Admin and GSP · Admissions** can **Mark as Primary**, asked first, which makes the student's other applications secondary; a student's first application is primary until then) with its 8 stages and the statuses inside them (who has each one, and which document arrives there), GSP's document requests, and **Add an application** with an eligibility check, the course's documents to upload and a new student added on the spot. GSP Assist, the AI, reads offer letters (including ones shared in the chat) and uploads, lays out the journey with likely dates, drafts student updates (English or Hindi) and answers in the chat, handing over to a person.
- **The portal while GSP verifies a new agency:** Home says verification is in progress and when to expect it. Students, Applications and Earnings stay locked in place until GSP verifies the business and its documents, and "View documents" shows every file sent with its status. Once verified, the locks open where they are.

The prototype opens on sign-in, in **light mode**, whatever the computer's own setting. Every screen has a Light / Dark switch, and the choice is remembered.

## Run it

```bash
cd designs/agency
npm install
npm run dev              # local dev server
npm run build            # type-check + static build in dist/
npm run build:artifact   # one self-contained HTML file in dist-artifact/ for sharing
```

The file to share is `dist-artifact/gsp-partner-portal.html` (about 500 KB). It starts with its charset and carries the code compressed, unpacked in the browser, so it opens the same whether it's downloaded and double-clicked, previewed in an app or published as an artifact; it needs a current browser (Safari 16.4 or later). `dist-artifact/index.html` also opens straight from disk, with no server needed. Its forms submit through script rather than the browser, so they also work in sandboxed previews (such as the Claude app's file preview), where the browser blocks ordinary form submission.

## Review states

Open the **Prototype** button (bottom right) to jump between states, switch theme, view a 390 px phone frame, and reset everything. States are grouped by area, and each group heading opens and closes its group; the group holding the state on screen starts open, the others closed. Each state also has its own link.

**Role** (the button beside Prototype, for testing) picks who the portal is seen as: **RP Admin**, the recruitment partner's admin, which is the agency portal everything below describes; **GSP Team**, GSP's own team; **GSP · Institution** (29 Oct), GSP's Institution Team: GSP Team members a GSP admin gives access to, who keep the records of the institutions GSP works with; **GSP · Admin** (30 Oct), GSP's admins: GSP's configuration, with the Institution Team's pages; or **RP Ops** (4 Nov), GSP's team for the recruitment partners, with the Institution Team's Applications, Students, Course search and Recruitment partners. GSP Team started as a copy of the agency portal (`src/gsp/`) and has since been reshaped for GSP without touching RP Admin. The Institution Team started as a copy of GSP Team (`src/institution/`) and has its own sign-in, pages and styles; nothing changed for it reaches RP Admin or GSP Team (Nesil's rule). GSP Admin is a copy of the Institution Team (`src/admin/`), its sign-in included, with its own colour. The role is remembered; switching it shows the same state in the other role, or that role's Home, signed in, from the sign-in pages. The review states and links work in either role.

**Connect RP Admin and GSP Team** (in the Role menu, for testing) makes one application (with its student) or all of them the same in both roles: GSP requests a document, changes the status or sends a document back, and the RP sees it; the RP uploads or writes in the chat, and GSP sees it. Each change also lands in the other role's bell (30 Oct). Switching role shows it in this window. **See both side by side** shows the two roles in two panes, where changes show in the other pane as they happen; another tab keeps up too. Opening side by side connects all applications unless one is picked. The latest change wins. The Role button says "connected" while it's on. Only copies of the **same build** keep up with each other (28 Oct): every downloaded copy shares the browser's storage, and an older copy left open in another tab used to send applications the newer one couldn't read (a status it no longer has), which left it blank. An application with a status this build doesn't have is left out too.

If a screen fails anyway, the page says so instead of going blank: **This screen didn't open**, with what went wrong (to send on), **Back to the screen** and **Start again** (`src/components/ErrorBoundary.tsx`). An error before the app starts says so too, in the shared file.

## Components: the same in every role (for developers)

Nesil, 4 Nov: every role uses the same pop-ups, dropdowns and buttons. Build each once and use it everywhere; the prototype does (`src/components/`).

| Component | The rule | In the prototype |
| --- | --- | --- |
| **Dropdown** (every select) | Never the browser's own list. The field (48px, white, the arrow on the right) opens a **white list that drops from the field**, as wide as it (or wider for a narrow field), with a tick on the current choice, groups under small headings, and choices that can't be picked greyed. It opens above the field only when there's no room below, and it's never clipped by a pop-up or a table. Keyboard: Arrow keys, Home and End, typing a letter to jump, Enter or Space to pick, Escape to close (the list only, never the pop-up it's in), Tab to move on. A click outside closes it. Filters' "All statuses" or "Any" is a choice in the list; a required field shows its placeholder (Choose, Pick a…) until something is picked | `Dropdown` and `SelectMenu` (`SelectMenu.tsx`); `SelectInput` (`forms.tsx`) for every form and filter, written like a native select. Compact variants, with the same list: the phone's dial code (its list as wide as the phone field), course search's student, Sort and search-bar fields, table-row cells, the Inbox's From |
| **Searchable dropdown** | The same list, with typing to filter, for long lists (country, university, RP) | `CountryCombobox`, `SearchPick` |
| **Pop-up** | A white panel in the middle of the window (a bottom sheet on phones): the title and a line under it at the top left, a **close icon in the top-right corner**, the content, and the **buttons at the bottom right**: Cancel (or Close, secondary) first, the main action last, on the far right. A note that goes with the buttons sits on their left. Escape, the close icon and the scrim close it; focus stays inside and goes back to what opened it. On phones the buttons share the width, the main one still last | `Sheet` (`Sheet.tsx`, `sheet.css`): every pop-up in every role is one |
| **Confirmation** | A small pop-up asking before something that's hard to undo (Delete, Set inactive, Unlink, Discard): the question as its title, what happens in a line or two, the close icon in the top-right corner (it cancels), Cancel and the action at the bottom right | `ConfirmDialog` |
| **Panels from the top bar** | The bell's and the megaphone's panels have the close icon in their top-right corner too, beside Mark all as read | `screens/portal/Inbox.tsx` |
| **Menus** | The three dots (More) and other small menus drop from their button, close on a click outside or Escape, and have no close icon: they're menus, not pop-ups | `MoreMenu` |

**Liquid Glass, used the way Apple's guidelines ask** ([HIG: Materials](https://developer.apple.com/design/human-interface-guidelines/materials), [Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)):

- **Two layers.** The photo and the statement are the content layer, edge to edge. The form lives in one glass panel, the control layer, floating 16 px in from the window. The panel is 420–500 px wide; the form is centred in it vertically, with equal space above and below. Nothing else on the page is glass except two small controls over the photo.
- **The right variant in each place:**
  - the panel and the brand pill use **regular** glass, because they carry text and coloured artwork;
  - the theme switch over the photo on phones uses **clear** glass with a dimming tint, which Apple reserves for controls over photos and video;
  - there is never glass on glass: the theme switch inside the panel is a plain control.
- **Background extension.** Under the panel, the photo is mirrored at its edge and blurred, as Apple does under sidebars beside hero images, so the glass picks up the photo's own warm and cool light. Nothing moves behind the panel, so that blur is done once, with the glass's saturation and lift baked in, rather than on every frame.
- **A lit edge.** The rim is brightest where light would hit, and it catches the pointer as it nears an edge. Its layer switches off when unlit, so filling in the form costs nothing.
- **Rounder controls,** as Liquid Glass has: capsule buttons, 12 px fields and a small toggle switch for "Keep me signed in" (38 × 22 px to look at, with a 44 × 32 px target). While pressed, its knob swells into a drop of glass, the guidelines' one exception for glass in the content layer.
- **Two lights in the glass:** upGrad red glows from the panel's top-right corner, with faint rings rippling out of it, and GSP blue from the bottom left. Their centres sit just outside the corners, and the footer uses the stronger grey, so all text over them keeps 4.5:1 or more (measured: 5.2:1 at the lowest).
- **The theme switch's thumb** slides between options on a spring.
- **Legibility comes first:**
  - labels on glass use their own meta colour (`--text-3-glass`), which holds 4.5:1 or more over the darkest part of the panel in both themes (measured: 5.2:1);
  - fields stay solid;
  - "Reduce transparency", "Increase contrast" and browsers without backdrop blur all get solid surfaces.

**Structure and alignment.** One grid sets every edge:
- the brand pill and the theme switch share a centre line;
- the statement and the panel footer share a bottom line;
- the statement and the brand pill share a left edge;
- the form, the switch and the footer share the panel's inner edges.

**Only what's needed.** The photo, the statement "The global marketplace for international student recruitment.", the form, and one footer line. The map, ticker and statistics from the previous version are gone.

**Two photos, taking turns** (Nesil, 27 Oct). A panorama of landmarks along one waterfront (a Gothic university, the Eiffel Tower, Big Ben, the Statue of Liberty, the Leaning Tower of Pisa, New York's skyline), then the student in Paris. The panorama is the original picture, untouched, extended with more of its sky above and its water below to 9:20, so all of it shows in every photo area, from a wide desktop or a split-screen window to the phone band. Each shows for 6 seconds, then the next fades in over 1.2 seconds; each has its own crop, so its student stays clear of the statement (and of the band's text on phones). Under the statement, a dot per photo: the one showing is a rounded bar that fills over its 6 seconds. Clicking a dot shows that photo; hovering or focusing the dots holds the current one. With reduced motion the photos don't change on their own (the dots still switch them). Registration shares the scene, so the photos and dots carry on there.

**The flows.**
- **Sign in:**
  - "Forgot password?" sits beside the password label;
  - show/hide password and a Caps Lock warning;
  - wrong passwords count down ("2 tries left") before a 15-minute pause with a reset button;
  - success shows a short welcome by first name.
- **Forgot password** has three steps with a progress bar; finished steps turn green.
  1. Username or email.
  2. A code sent to the hidden email (n••••@…).
  3. A new password, then "Type it again", then one hint line: "Use at least 8 characters, with upper and lowercase letters and a number." The hint is grey while you type, green once it's met, and red if you try to save without meeting it.

  The flow returns to sign-in with the username filled in.
- **New agencies** use the "Become a GSP partner" button, which opens registration. Registration links back with "Already a partner? Sign in".

**Phone.** The photo becomes a band with the brand pill and a clear-glass theme switch on it. The panel becomes a glass sheet over it, sitting on the photo's extension mirrored downwards.

**Motion** (`animation-library-by-nesil`): one load moment, then stillness, apart from the photos' slow crossfade.
- **Order:** the photo settles in (a 1.04 zoom), the panel floats in, the brand pill appears and the statement rises line by line.
- **Timing:** the sequence waits for the photo to decode, so the content is always there before the glass floats over it.
- **Reduced motion:** everything is simply there.

**Performance.** These numbers were measured in a container with only a software GPU (SwiftShader):

- **Pointer over the page and filling in the form:** 56–61 fps.
- **The 2-second load sequence:** about 38 fps. The cost is resampling the full-size photo in software, which a hardware GPU does for free.

## Design decisions: the student record

**4 Nov (3rd round), every role:** Academics' state or province, grading system and score are optional; English test asks first "Has the student taken an English test?" (No: an optional tentative test date; Yes: the tests); no Share with student.


**4 Nov (Nesil), RP Admin only:** **Background** asks, each in its own card: **Marital status*** (Single, Married, Divorced, Widowed, Separated) and, when married, **Date of marriage***; **Has the student ever been refused a visa, for any country?*** and, when yes, each refusal's **country**, **which visa or document** and **when** (Add another refusal); **Will a spouse or dependents go with the student?** and how many; **Does the student have a disability or long-term health condition?** (No, Yes, Prefer not to say) and what support might help. The required ones block Save and count in the profile's completeness. Removing a saved document, job, test, education or refusal asks first.


Every student has a record, filled in over time. Above it, "← Students" on the left and **Share with student** on the right (it copies a link where the student fills in their own details; the button says "Link copied" for a moment). Its header, in the same brand light as the Find courses search card, has the name, ID, nationality, who added them and when, then one line of email and phone (each with copy), with the counsellor as text and a pencil at the right end of the same line (changing it asks first; on phones it goes under the phone number). On the right, **Find courses for {first}** (the search takes their country and state) and **Start application**, which opens Add an application with the student picked; they drop below the name when there isn't room. Under it, one ring says how ready the profile is ("Profile 46% ready", or "Profile complete: ready to apply"). The percentage counts only the mandatory fields and documents, which are all in Personal details and Education; the optional sections don't move it.

Below the header, there's **no bulk upload** (Nesil, 29 Oct; it led the record from the 27 Oct review until then): documents uploaded all at once in Add a student are already filed and read into their sections, and each section uploads its own. Files sorted from Add a student go to the section they belong to: the passport to Personal details, marksheets and transcripts to Education (a lower level's card appears when its marksheet arrives), score reports to Tests (a test is added if there isn't one), each read into its fields; the CV is kept in Additional documents and its jobs are read into Work experience; the SOP, letters of recommendation and work letters go to Additional documents, and so does anything that isn't part of a section (including a level above the highest education). There's no note saying where they went (Nesil, 29 Oct): Documents shows them. "{name} added · Complete the student's profile." is a notification, bottom left, that goes by itself after a few seconds. No part of Personal details has a line under its title (Nesil, 29 Oct); under the highest education: "The highest education is required. Other levels are optional." Where they live has no explanation line.

The menu beside it has **three things** (Nesil, 29 Oct; a scrolling row on phones): **Personal details**, **Documents** and **Applications**. Personal details and Applications have **tabs inside** (knowingly against the "no tabs inside tabs" Decision, Nesil's choice when asked; noted in REVIEW.md): Personal details in **Personal, Academics, English test, Work experience** and **Background**; Applications in **My applications** and **Shortlisted**. Each tab of Personal details carries a green tick when complete, an amber dot when a mandatory field is missing, nothing when it's optional and empty, or "Unsaved". **Documents are only in Documents** (Nesil, 29 Oct): no part of Personal details shows a file. **The first time**, before a part has its document or any details (Personal before the passport or its details, each Academics level, each test, Work experience before a CV or a job), it offers to fill itself in from its document ("Fill this in from the passport", "…from the undergraduate transcript", "…from the score report", "…from the resume"); after that it's edited by hand, with no upload. A part filled in from a document (by its own upload or by the bulk upload in Add a student) says so in one line ("Filled in from the passport, which is in Documents. What was read is highlighted: check it."). **A section with anything saved in it is read-only**: the same fields shown as text (no boxes, hints or buttons; only the picked option; "Not added" where nothing is), with **Edit** beside the title. What a section adds sits at its top, beside the title: **Add education** (a menu of the levels not on the record yet: Postgraduate, Undergraduate, Grade 12, Grade 10), **Add job**, and **Add test** (a menu of the eight tests). Adding opens the section for editing with the new card in the draft, focused on its first field. Edit opens the form on a draft, focused on the first field; **Save** keeps it ("Saved" shows in the header for a moment), **Cancel** throws it away, and a draft survives switching tabs until one of the two. An empty section opens straight on the form, with Save once something's entered. Saving one section only changes that section. **People act; GSP moves the status.** Sending the documents in New moves the application to Pre-screening; everything after is GSP's to move. A document GSP asked for goes to GSP the moment it reads as right. Withdrawing asks why. **Every document**, in either role (Documents, the chat, the conditions, GSP's mail), can be **previewed** (a stand-in for its first page) and **downloaded** (a one-page PDF in this prototype).

**Not yet:** the student's own view, bulk actions (assign, chase), Earnings, and the GSP side that creates document requests.

## Design decisions: Inbox (GSP roles)

- **Categories** (5 Nov): GSP sorts each mail as it arrives. **Not linked**: GSP couldn't place it (the default when nothing else fits). **Linked to an application**: matched, or linked by hand. **Forwarded**: sent on to another inbox. **Others**: miscellaneous, not about an application. A **Category** dropdown sits after the email group, each category with its count; neither dropdown has a label above it. A Not linked mail shows a nudge above its text: **Link it to an application** (students the mail names first), an **or** divider, then **Forward it to another inbox**, with both buttons and both dropdowns the same width; pressing either with nothing chosen says what to choose. Linking shows the application's card; forwarding notes where it went and puts a copy, unread and Not linked, in that inbox. Sample mail in every role's starting inboxes covers all four.

- **Mail threads** (5 Nov): a mail can be a thread of replies and follow-ups. In the list, a thread's row names who wrote (“Deakin University Offers, Alfiya Khan”, with “me” once you've replied) and shows how many messages it holds.
